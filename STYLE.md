# Style Guide

## Definitions
- `component`: A subsystem of the Laravel framework such as `Illuminate\Routing\Router`
- `manifest`: A YAML file that is a **body** on the root receiver, `Illuminate\Foundation\Application`
- `root receiver`: The one object the provider hands to `body()`: `$this->app`. Every root key is one of its methods, or a data key, or a projected FQCN addressed statically
- `body`: `$t->a(); $t->b();` — a map of **native method** names to argument values, applied to one receiver in manifest order (`Engine::body()`)
- `chain`: `$t->a()->b()` — the keys of a row that are not parameter names ride the call's return value (`Engine::chain()`)
- `row`: A map whose first key is a parameter name of the **native method**: one call with named arguments; the other keys chain
- `entries`: A map whose first key is not a parameter name of a method with two or more parameters: one `->method($key, $value)` call per entry
- `λ`: A map under a closure parameter is a body on the closure's argument (`afterResolving: {FQCN: {…}}`, `create: {users: {…}}`, `registered: {…}`)
- `Σ` (signature): Per **native method**, `{static, params: [{name, type, variadic}]}`, extracted by PHP-Parser at generation time and carried in the schema as `x-manifest`; the runtime reads it from there and never re-reads vendor
- `forms`: The one ordered decision list (`Forms::calls()` / `Forms::schema()`) that maps `Σ[m] × value → calls` and emits the schema rows for the same key
- `native method`: The real Laravel method a key forwards to; source of truth for key casing, signature order, optionality and types
- `curation`: Per-key schema data that survives regeneration byte-for-byte: `description`, `pattern`, `enum`, … and the `x-manifest` keywords `form`, `list`, `order`, `closure`, `resolve`, `data`
- `vocabulary`: The shared definitions a curated `resolve` names: `closure`, `phpFile`, `concrete`, `path`
- `data key`: A root key flagged `x-manifest.data` (`requests`, `models`, `queries`, `schema`, `extra`): stored in `ManifestStore`, never dispatched
- `schema`: `manifest.schema.json` — generated by `declaration:generate-manifest-schema`, the only validation layer, and the runtime's signature source

## Highest Value

**PURE STATELESS LARAVEL FRAMEWORK DECLARATIVE API MAP**
This package is a thin, stateless, declarative wrapper over Laravel's public API.
- Keys map to function names
- Values map to function signatures
- Forward data to Laravel. Nothing more.

### Rule 0 — Declarative projection
- 0.1 Project native Laravel classes 1:1.
- 0.2 Project native Laravel contracts 1:1.
- 0.3 Project native Laravel registries 1:1.
- 0.4 Every projected definition `definitions.<FQCN>` is one Laravel class, every key one of its public methods (own, traits, parents).
- 0.5 If a capability exists in Laravel, map it by adding the class to the generator's scope.
- 0.6 Never replace a Laravel capability with glue or synthetic keys.

### Rule 1 — Key = method name
- 1.1 The **manifest** key and the **native method** name are **identical strings**.
- 1.2 The schema key (`definitions.<FQCN>.properties.<m>`) and the **native method** name are **identical strings**.
- 1.3 The definition key is the FQCN, verbatim.

Identical strings:
- `middlewareGroup`
- `aliasMiddleware`
- `prependMiddlewareToGroup`
- `addRoute`
- `resource`

- 1.4 No invented verbs or nouns.
- 1.5 If Laravel doesn't have that method name, the key is wrong (schema-invalid; at runtime it fails with PHP's own exception).

### Rule 2 — Argument forwarding
- 2.1 Pass references through untouched, except through a curated `resolve` vocabulary.
- 2.2 Pass scalar arguments through untouched (`methods: GET` is passed verbatim; nothing uppercases).
- 2.3 Signature order comes from the **native method**.
- 2.4 Optionality comes from the **native method**.
- 2.5 Types come from the **native method**.
- 2.6 Never reshape arguments.
- 2.7 Never default arguments.
- 2.8 Never normalize arguments.

### Rule 3 — Fail where Laravel fails
- 3.1 No custom DSL.
- 3.2 No custom validation layers.
- 3.3 Propagate native exceptions (`BadMethodCallException` on dynamic dispatch, `ArgumentCountError`, `TypeError`, Fluent silence).
- 3.4 No validation.
- 3.5 Pass everything through.

### Rule 4 — Stateless, immutable, cache-safe
- 4.1 The engine holds the decoded schema and the container; nothing else.
- 4.2 The provider only applies the manifest in `register()`; every later timing is a lifecycle call the manifest makes itself.
- 4.3 No request-time state.
- 4.4 No singletons mutated at runtime.
- 4.5 Fully compatible with `route:cache`.
- 4.6 Fully compatible with `config:cache`.
- 4.7 Do not cache classes — only native php types (a `closure` reference stays a string until called).

### Rule 5 — Zero cross-subsystem orchestration
- 5.1 Pure registration and configuration.
- 5.2 One body wires one receiver.
- 5.3 No component reads routes of another **component**.
- 5.4 No component reads queries of another **component**.
- 5.5 No component reads responses of another **component**.
- 5.6 Timing is written in the manifest with the application's lifecycle methods (`make`, `registered`, `booting`, `booted`, `afterResolving`); the package has no block map and no dispatch configuration.

### Rule 6 — Optionality
- 6.1 Everything in the **manifest** is opt-in.
- 6.2 Missing keys do not throw exceptions: behavior is simply not triggered. A present key with `null` (or `true`) calls with no arguments; absence is the only opt-out (`false` is a scalar and calls).
- 6.3 Missing values must be handled by the **schema**.
- 6.4 It is assumed the **manifest** is validated by the **schema**.
- 6.5 No runtime validation.

## Highest Order Techniques

### Rule 7 — The forms: one ordered decision list
Nothing in the package may branch on a component, a method name, an attribute or a typed class. Generation and runtime are two callers of the same table; both derive from `Σ` and the curation, first match wins:

| # | value | condition | calls |
| --- | --- | --- | --- |
| 1 | `null` \| `true` | — | `m()` |
| 2 | scalar | — | `m(ρ(value, p0))` |
| 3 | list | `p0.type = array` ∨ `list: argument` | `m(value)` — the list IS the argument |
| 4 | list | `p0` variadic | `m(...ρ(item, p0))` |
| 5 | list | otherwise | one call per item; a map item is a row |
| 6 | map | first key ∉ names(P) ∧ `form: entries` | `m(k)`, the value is a body on the return |
| 7 | map | first key ∉ names(P) ∧ n ≥ 2 ∧ `p0.type ≠ array` | entries: `m(k, ρ(v, p1))`; a list value fans out; a map under a closure `p1` → `m(k, λ(v))` |
| 8 | map | first key ∉ names(P) ∧ `p0` is closure | `m(λ(value))` |
| 9 | map | first key ∉ names(P), otherwise | `m(value)` — the map IS the argument |
| 10 | map | first key ∈ names(P) | row: `m(...named)`; the other keys chain on the return |

- 7.1 `Forms::schema()` EMITS every row a key admits (`anyOf`); `Forms::calls()` PARSES the one row a value takes.
- 7.2 `ρ` resolves a value through the curated `resolve` vocabulary for that parameter (default: `closure` for closure parameters, untouched otherwise).
- 7.3 `λ` wraps a map as `function (object $o) { body($o, map) }`.
- 7.4 An unknown key (a `__call` surface such as Fluent) dispatches as `(...$arguments)` — PHP decides.
- 7.5 Behavior never lives in `match`/`switch` chains over names.

### Rule 8 — The data the core consumes
- 8.1 `Σ` is hierarchy-inclusive (own methods, traits, parents; own wins) in `ReflectionClass::getMethods()` order; the gate is public ∧ not `__*` ∧ not `@internal` ∧ no by-reference parameter; zero-parameter methods are declarable.
- 8.2 Generation is total: every declarable method of every class in `x-manifest.classes` is projected; `--check` regenerates and compares bytes.
- 8.3 The only per-key curation the forms admit, all schema data, all preserved by re-merge: `form: entries` · `list: argument` · `order: reverse` · `closure: [param…]` · `resolve: {param: closure|phpFile|concrete|path}` · `data: true` (root keys only).
- 8.4 Curated `description`, `pattern`, `enum`, … survive regeneration byte-for-byte; the structural shape (`anyOf`, `type`, `items`, `properties`, …) is always regenerated — never hand-edit a shape, regenerate.
- 8.5 Add a Laravel method by regenerating; add a Laravel class by adding its FQCN to the scope — no new dispatch code.
- 8.6 The root is `$ref`s to the root receiver's keys ∪ the curated data keys ∪ every projected FQCN with a static key (a static receiver).

### Rule 9 — Exact vertical naming & casing
- 9.1 Schema key = **manifest** key = native Laravel method name (Laravel's own casing).
- 9.2 Classes `PascalCase`.
- 9.3 Method keys `camelCase` (Laravel's casing, never ours).
- 9.4 Local variables `camelCase`; a variable holding a Laravel service may be `PascalCase` (`$Router`).
- 9.5 Engine code lives in `Internal\Engine`; seams (`DeclaredRequest`, `DeclaredModel`, `DeclaredQuery`, `DeclaredView`) read `ManifestStore`.
- 9.6 The generated key description states the exact native call: `-> middlewareGroup($name, $middleware), one call per entry …`; curated prose refines it, never contradicts it.

### Rule 10 — Argument forwarding
- 10.1 The engine forwards values verbatim:

```php
foreach ($this->calls($meta ?? Forms::VARIADIC, $value) as [$args, $rest]) {
    $result = $static ? $t::{$key}(...$args) : $t->{$key}(...$args);   // native failure propagates (Rule 3.3)

    if ($rest !== []) {
        $this->chain($result, $rest);                                   // extra keys ride the return value
    }
}
```

## Canonical Skeleton

1. `src/Internal/Engine/Signature.php` — `Σ[m]`: `name`, `static`, `params`.
2. `src/Internal/Engine/Forms.php` — the one table: `schema()` emits, `calls()` parses.
3. `src/Internal/Engine/Resolve.php` — `ρ`: the four vocabularies; container-free except `call` and `path.base`.
4. `src/Internal/Engine/Engine.php` — `body`, `chain`, `λ`, `def`, `isStaticReceiver`, an optional `guard` hook for commands.
5. `src/Internal/SchemaGenerator.php` + `declaration:generate-manifest-schema` — total generation with curation re-merge.
6. `src/Providers/ManifestServiceProvider.php` — the only call site: `$engine->body($this->app, $store->all())`.
7. `src/Internal/ManifestStore.php` — the raw manifest for the data keys.
8. Feature tests proving native exception behavior, lifecycle timing and cache-safety; the oracle suites keep their assertions when a form changes.

## Checklist before shipping a new mapping

- [ ] Every key matches a **native method** name character-for-character; the class is in `x-manifest.classes`.
- [ ] Arguments forwarded untouched; curation (`resolve`, `closure`, `order`, `list`, `form`) is schema data, not code.
- [ ] Failure mode is Laravel's (native exception), not a bespoke message/DSL.
- [ ] No `match`/`switch` added where the forms table already decides.
- [ ] Shapes regenerated, never hand-edited; prose curated in the schema.
- [ ] `composer check` passes (pint, rector, phpstan, 100% coverage, `declaration:generate-manifest-schema --check`).
