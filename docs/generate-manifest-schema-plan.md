# Generate Manifest Schema Command — Whole-File Plan

> **Superseded.** This plan is superseded end to end by [general-purpose-migration-plan.md](general-purpose-migration-plan.md): the schema is now total (every declarable method of every projected class, parents included), FQCN-keyed, regenerated by `declaration:generate-manifest-schema` from `x-manifest.classes`, and the runtime maps the manifest back onto the same signatures (§1 of that plan). Kept for its vendor findings only.

## 0. State

The command exists: [src/Internal/Commands/GenerateManifestSchemaCommand.php](../src/Internal/Commands/GenerateManifestSchemaCommand.php)
(104 lines) — `declaration:generate-manifest-schema {classes*}`. Its engine is
[src/Internal/SchemaGenerator.php](../src/Internal/SchemaGenerator.php) (549 lines):
`render($class, $source)` returns a complete, source-order definition fragment for an
FQCN; `skipped($class, $source)` returns the native methods excluded by the declarable
rules; `merge($schema, $class, $fragment)` appends the fragment's missing keys under
`definitions.<FQCN>` preserving curated key objects byte-for-byte; `encode($schema)`
prints the repo's 2-space JSON with a trailing newline.

The command is **append-only** by design: it never removes a curated key, never rewrites
a curated key object, never touches the root `properties` wiring, and only generates
definitions whose key is the FQCN verbatim. That design was chosen for one purpose —
*add newly-arrived native methods to definitions that already exist*. It cannot be the
generator for the whole file.

This plan makes it the generator for the whole file without losing the append-only
engine. The engine stays exactly as it is (append-only merge, byte-identical when
nothing changed). The command's **run order** changes: remove curated keys first, then
generate each scoped definition from its source class, then re-merge curated keys from
the schema-as-it-was — restricted to keys that are real native methods (`declarable(...)[0]`
— including `skipped()` ones, since a skipped key is still native and curation is allowed
to declare it: `skipped()` means *zero params or byRef*, not *not a method*). Append-only
merge over a freshly-generated fragment is the same `merge()` call the command makes
today — append-only becomes an **implementation detail** of the re-merge, not the run
order.

Everything here is a plan over the current source code — no code is implemented by this
document.

## 3. The run order (the one change)

Current command, per scoped class:

```
pre-flight: resolve the source file for $class; fail the run on the first unreadable class
read:       parse manifest.schema.json (the file is never rewritten when nothing changed)
skipped:    SchemaGenerator::skipped($class, $source) — the excluded native methods, never written
render:     SchemaGenerator::render($class, $source) — the full source-order fragment
merge:      SchemaGenerator::merge($schema, $class, $fragment) — append missing keys under definitions.<class>
encode:     SchemaGenerator::encode($schema) — 2-space JSON + trailing newline
write:      manifest.schema.json (the file is never rewritten when nothing changed)
```

Whole-file plan, per scoped class:

```
pre-flight: resolve the source file for $class; fail the run on the first unreadable class
read:       parse manifest.schema.json
generate:   SchemaGenerator::render($class, $source) — the fragment replaces the definition's `properties` wholesale
re-merge:   curated keys from the schema-as-it-was — gated on native declarability (declarable(...)[0] + skipped())
            keys preserved byte-for-byte; keys absent from the fragment land as undecided (description-only + TODO)
report:     native-only (native methods not in the schema) — a drift report, never auto-added
            curation-only (curated keys with no native method) — preserved, reported
            native-but-not-declarable (curated keys mapping to protected/skipped native methods) — preserved, reported
            TODO keys (undecided shapes) — left to curation, reported
encode:     SchemaGenerator::encode($schema)
write:      manifest.schema.json (the file is never rewritten when nothing changed)
```

The decisive difference: the fragment is generated **first**, then curated keys are
re-merged on top. Append-only merge over a freshly-generated fragment *is* the re-merge —
`merge()` needs no new behavior. The plan's new code is the **scope** (the FQCN-gated
definition selection), the **re-merge gate** (curated keys are byte-for-byte preserved;
absent curated keys land as native-declarable or curation-declared), and the **drift
report** (native-only, curation-only, native-but-not-declarable, TODO).

## 4. The scope — what the command generates

The scope is the `classes*` list, exactly as today. The plan's scope mode:

1. **Definition key = the FQCN verbatim** (§2.3 of the engine). A definition in scope is
   `definitions.<FQCN>` for each `$class` in `classes*`. A curated-named definition is
   never in scope — the plan reports it as `out of scope` and does not mutate it.
2. **The definition's `properties` map is regenerated wholesale** from the source class —
   the fragment's `description`, `type`, `additionalProperties`, and `properties` replace
   the definition's fields. Curated key objects are re-merged on top (byte-for-byte).
3. **A definition that does not exist yet is created** — `merge()` already creates it
   (`definitions[$class] = $fragment`). A definition that exists is replaced then
   re-merged.
4. **The definition's `$ref` wiring at the root is untouched** — the plan never rewrites
   root `properties`. A definition emptied/removed by scope-regeneration leaves a dangling
   root `$ref`; the plan reports it (a `--check` item) and the hand-authored
   `src/Manifest.php` wiring removes it.
5. **Sub-definitions, `config`, and `extra` are never in scope** — they are out of scope
   by definition (§2 items 9–11). The plan never generates, deletes, or rewrites them.

## 5. The re-merge gate

The fragment replaces the definition, then curated keys are re-merged on top. The gate is
**native declarability**:

| Curated key state | Gate result | Plan behavior |
| --- | --- | --- |
| Key is in `declarable(...)[0]` — the fragment has it | native-declarable | Fragment's shape wins; curated `description` prose is **preserved byte-for-byte** (append-only merge semantics, inverted: the curated description replaces the fragment's description on the key the fragment generated). |
| Key is in `skipped()` — native but zero-param or byRef | native-but-not-declarable | Key is re-merged **byte-for-byte** from the schema-as-it-was (curation may declare a skipped key; the plan never invents public surface). Reported. |
| Key is native but not declarable (non-public, `__*`, `@internal`, or parent methods — rules 1–4; the fragment has no such key and `skipped()` has no such key: rules 1–4 are excluded silently, never anywhere) | native-but-not-declarable | Key is re-merged byte-for-byte. Reported. The plan never invents public surface — curation may mirror it, the plan may not. |
| Key has no native method at all (`$class->hasMethod($key)` false on the source class and its traits) | curation-only | Key is re-merged **byte-for-byte** from the schema-as-it-was. Reported. Never deleted. |
| Key is in the fragment with a `TODO(<method>: <params>)` description and the curated schema had a real shape for it | undecided shape | Curated shape wins — the TODO description is replaced by the curated description (which carries the shape's prose). Reported. |

The gate reads the **source class**, not the schema: `declarable(...)[0]` and `skipped()`
are per-class lists from the engine, and `hasMethod` is checked against the same
`flatten()` result the fragment was generated from. One `render()` run produces
everything the gate needs — the plan does not re-parse the source.

Byte-for-byte preservation is the invariant: a key object the schema-as-it-was had is
re-merged exactly as it was — description prose, `$ref`s to sub-definitions, `anyOf`
shapes, TODO-free descriptions. The fragment's generated shape is *never* a reason to
rewrite a curated key object; the curated shape always wins on a native-declarable key
whose fragment shape differs.

## 6. The drift report

The command's report has four sections, printed when `--report` is passed and printed
per-class when a class produced drift. The report is never a failure — it is information
the caller acts on (the engine's skipped() is the precedent: reported, never silent).

| Section | Source | Meaning |
| --- | --- | --- |
| `native-only` | `flatten($class)[method]` names not in the schema-as-it-was definition's `properties` and not in the fragment's TODO keys | Native methods the schema does not declare. Never auto-added — a manifest key the providers don't forward is a lie (the engine's `declarable()` is the gate; `render()` never auto-adds). |
| `curation-only` | schema-as-it-was definition's `properties` names not in `flatten($class)` | Curated keys with no native method. Preserved byte-for-byte, reported. |
| `native-but-not-declarable` | schema-as-it-was definition's `properties` names in `skipped()` or native-but-not-public | Curated keys mapping to native methods the engine excludes. Preserved byte-for-byte, reported. |
| `TODO` | fragment keys whose description contains `TODO(` | Undecided shapes — the key is native and the schema declares it, but its value shape is unknown. Left to curation, reported. |

Out-of-scope definitions (curated-named, sub-definitions, `config`, `extra`) are reported
once per run as a fifth section, `out of scope`, listing the definition names the plan
cannot project. The `out of scope` section is never a failure.

## 7. Idempotence and the no-change fast path

The engine's invariant — the file is **byte-identical** when nothing changed — is the
plan's fast path:

1. Parse the schema file.
2. Per scoped class: generate the fragment, compute the re-merged definition.
3. If the re-merged definition is `===` the definition-as-it-was (the array compare the
   engine's merge already performs per key), skip the write for that class.
4. If **every** scoped class skipped, skip the encode and the write entirely — the file is
   never touched (mtime unchanged).
5. If any class changed, encode and write once.

The `--report` flag prints the drift report without writing — the `--check` fast path
plus the report. There is no `--dry-run` separate from `--report`: the report is the
dry run, the write is the same run without `--report`.

| # | Failure | Raised when | Message |
| --- | --- | --- | --- |
| 1 | `RuntimeException` no readable source for $class | pre-flight, per scoped class | `No readable source for $class` |
| 2 | `RuntimeException` $class is not declared in its resolved source | pre-flight, per scoped class | `$class is not declared in its resolved source` |
| 3 | `PhpParser\Error` the source is not valid PHP | pre-flight, per scoped class | native PhpParser error |
| 4 | a scoped class resolves to a curated-named definition key | never — the plan's scope is FQCN-gated by construction | the plan reports it as `out of scope`, never fails |
| 5 | a trait's source is missing, unreadable, not declared, or an adaptation dangles | during `flatten()` (the engine's existing throws) | the engine's messages, unchanged |

Failures 1–3 are pre-flight: the run fails **before** the schema file is touched. The
schema file is never partially written, never left unparseable, never left with a
dangling definition.
